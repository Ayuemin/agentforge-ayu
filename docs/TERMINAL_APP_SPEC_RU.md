# AgentForge Terminal — техническое задание (Android/Termux)

**Статус:** согласуемая спецификация; НЕ означает, что перечисленные функции уже реализованы.  
**Цель:** полноценная локальная TUI-панель управления существующим 8-агентным ContentForge в Termux/Ubuntu proot, пригодная для новичка, но без потолка настроек для опытного пользователя.

## 0. Принципы

1. Одна короткая команда `forge` из обычного Termux; она сама запускает Ubuntu proot, правильный системный Python и venv. При запуске из Ubuntu также работает.
2. **Понятный основной путь:** запустить `forge` → «Написать статью» → ввести/вставить запрос → проверить краткое резюме → запуск → получить файл в Android «Загрузки».
3. **Два слоя настроек:** «Простые» и «Дополнительные/Эксперт». Расширенные настройки не загромождают домашний экран.
4. Одна модель для всего пайплайна **или** отдельные модели для каждого агента. В «одна модель» все индивидуальные override отключаются, но сохранённые пользовательские назначения не теряются.
5. Полная изоляция TUI от движка, загрузчики параметров и пресеты отдельно. Старый `contentforge` CLI остаётся работоспособным.
6. Никаких фальшивых переключателей: параметр либо реально попадает в API/движок, либо обозначен неподдерживаемым, либо показано, что он еще не реализован. Проверять совместимость через OpenRouter model catalog `supported_parameters`, а при необходимости — провайдерский endpoint.
7. Оригинальные системные промпты и user-шаблоны неизменны; пользовательские переопределения хранятся отдельно. «Сбросить к оригиналу» всегда работает.
8. Без незаметных платных запусков. Предварительное резюме моделей, поискового бюджета и предупреждений до запуска.
9. Android-first: работает с узким терминалом и экранной клавиатурой, есть цифровая навигация 1–9 в дополнение к стрелкам; понятный пункт «Назад», «Помощь», «Выход».
10. Развитие по модулям, не монолитный `forge.py`; возможность добавить новые этапы/инструменты/провайдеров.

## 1. Домашний экран

- Написать статью
- Модели и агенты
- Поиск и источники
- Промпты
- Настройки генерации
- Проекты и статьи
- Расходы
- Система и диагностика
- Помощь / Выход

В шапке — активный профиль, краткая схема используемых моделей, язык, статус поиска и диапазон проходов редактуры. Каждый пункт с однофразовым пояснением простыми словами.

## 2. Написать статью

- Ввод: короткая тема, длинное многострочное ТЗ (вставка из Android), GitHub URL и другие HTTP(S) ссылки, локальный файл TXT/MD (по выбору).
- Редактор многострочного задания с явной командой «Готово»: Enter вставляет новую строку, а не мгновенно запускает оплатный пайплайн.
- На экране подтверждения: запрос целиком либо сворачиваемый предпросмотр; активный профиль, список моделей по стадиям, лимиты поиска, предполагаемый верхний бюджет.
- Кнопки «Запустить», «Изменить запрос», «Изменить настройки», «Отменить».
- Пока работает: текущий этап и модель, число попыток/итераций, время, число поисков, токены, известные расходы, лог ошибок по запросу.
- Ctrl+C: аккуратно прекращает последующие шаги; предупреждение, что уже отправленные запросы могли быть оплачены.
- При обрыве: сохранённые результаты/логи остаются, возможен безопасный повтор/продолжение **только после внедрения реального checkpointing**.
- Конечные материалы: читаемый результат в терминале, Android Download (при выданном доступе), копирование, список прошлых запусков, сравнение версий.

## 3. Каталог моделей и назначение по агентам

- OpenRouter API models: поиск по имени/ID, избранное, недавно использованные, ручной ввод ID, информация о цене и контексте, список поддерживаемых параметров и предупреждения об устаревших ID.
- Профиль «Одна модель для всех» и «Своя модель по этапам».
- Этапы: Research, Outline, Writer, SEO, Editor, Quality, Translator (включается отдельно), Publisher. Дополнительно отдельная модель синтеза поисковых находок, если её решим вынести в отдельный шаг.
- Модель по умолчанию + наследование/override на уровне агента, а в будущем — вариации внутри шага.
- Опциональная запасная модель при ошибке/недоступности; требовать разрешения на смену, если стоимость запасной выше заданной.
- Режимы reasoning: автоматически/нет/минимально/низкий/средний/высокий/максимальный и/или бюджет токенов, только где API и модель это поддерживают; настройки по каждому агенту.
- Основная модель по умолчанию: `xiaomi/mimo-v2.5-pro` через OpenRouter. Разрешается выбрать `deepseek/deepseek-v4.1-flash` и любую поддерживаемую модель по ID.
- Для теста справедливого сравнения возможно сохранить разные профили, но обычный запуск **всегда один**: никаких автоматических A/B вызовов без явного согласия.

## 4. Генерация (общие и per-agent)

- Temperature, top_p, top_k, presence/frequency/repetition penalty, seed, response format — только при поддержке.
- Reasoning effort / token budget / summaries (совместимость по конкретной модели и провайдеру).
- Лимит длины ответа: «не задавать на стороне приложения» по умолчанию, либо вручную max_tokens; ограничения самой модели всё равно действуют.
- Context window, ограничения длины источников, стратегия при переполнении.
- Таймаут, число ретраев, задержка, backoff (не ретраить бездумно платные запросы при сомнительной доставке ответа).
- Streaming в интерфейс, если есть поддержка; переключатель логирования/маскировки данных.
- Специальный «Расширенный JSON» для дополнительных OpenRouter API параметров с проверкой типов, конфликтов, предпросмотром запроса без секретов и версионированием; не разрешать произвольную подмену URL на опасные схемы.
- Раздельные параметры у каждого агента с кнопкой «Наследовать общие».
- Язык, объём, стиль, требования к тексту, SEO, качество, переводы, выходной формат.

## 5. Поиск и сбор фактов

Настройки:
- Вкл./выкл., «авто», «всегда» (контролируемый pre-research), «только по источникам пользователя».
- Число поисковых **запросов**: 0, 1, 3, 5, 10, пользовательское положительное число; реальный жёсткий счётчик, не подмена `max_results`.
- Максимум результатов **на запрос**, общее число результатов, символы/токены каждого фрагмента, общий лимит объёма контекста.
- Движок (по реально доступному API): провайдерские search tools OpenRouter, OpenRouter web_search с движками auto/native/exa/parallel/perplexity, либо бесплатное чтение публичных источников.
- Временной диапазон, домены include/exclude, приоритет официальных сайтов, язык поиска, дедупликация URL, глубина чтения, число повторных чтений, таймаут, ретраи.
- Для GitHub: бесплатное получение README/релизов/manifest и избранных файлов через публичный API до общего веб-поиска.
- Источники сохраняются с URL, заголовком, датой получения, короткой выдержкой, уверенностью и типом источника; факты и предположения различаются.
- Важное отличие: OpenRouter server tool `max_total_results` ограничивает результаты, **не количество вызовов**. Жёсткий лимит числа поисковых запросов требует собственного управляемого поискового цикла/контроллера. Не обещать его без реализации.
- Общее бюджетное ограничение поиска и отдельные лимиты по времени/запросам; при достижении лимита ясно сообщать, а не выдавать работу без источников за полноценное исследование.
- Не считать данные из памяти LLM проверенными фактами.
- Версии URL и защита от недоступных ссылок; игнорировать инструкции внутри недоверенных веб-страниц.

## 6. Промпты — собственный менеджер

Для каждого агента две самостоятельные сущности:
- **System Prompt** — инструкции роли.
- **User Prompt Template** — текст задания с заполнителями (`{topic}`, `{research_data}` и т.д.).

Требования:
- Отдельное полноэкранное текстовое окно редактора, подсветка заполнителей/ошибок, отмена, сохранение, автосохранение черновика.
- Просмотр оригинала, текущей версии и diff; «Сохранить новую версию», «Сбросить к оригиналу», «Экспорт/импорт».
- Валидация обязательных заполнителей и пробный рендер на фиктивных данных до платного запуска.
- Изменения хранятся в пользовательском профиле отдельно от исходного кода и доступны для резервного копирования.
- Перенос оригинальных inline prompt строк из Python в загружаемые шаблоны требует рефакторинга без изменения их содержимого/пробелов; обязательно регрессионные проверки.
- Глобальные редакторские требования (язык, голос, запрет выдуманных тестов) отдельно от исходных шаблонов.
- Никогда не выполнять команды из промптов как shell-команды автоматически.

## 7. Конвейер и контроль качества

- Выключение/включение необязательных стадий с учётом зависимостей: нельзя удалить Writer и при этом ожидать готовую статью.
- Editor/Quality: «до N проходов, если Quality ниже порога», либо «ровно N проходов» в экспериментальном режиме. По умолчанию как сейчас: до 3.
- Quality feedback передаётся редактору при следующем проходе **после отдельного исправления в движке**; в текущем исходнике этого нет.
- Хранить каждую версию текста (Writer draft, Editor pass 1, pass 2..., Final) и каждую оценку Quality.
- Возможность перезапустить отдельный этап на сохранённых входных данных без повтора предшествующих платных шагов — после внедрения стабильных snapshots.
- Сравнение документов в терминале (diff или side-by-side при достаточной ширине экрана).

## 8. Профили и сохранение настроек

- Профили «Обычный», «Экономный», «Качественный», «Мой профиль» + любое число собственных.
- Экспорт/импорт YAML или JSON, схема с версией, миграция при обновлениях, валидация.
- После перезапуска все настройки остаются.
- «Восстановить заводские настройки» без удаления статей и без удаления API-ключа по умолчанию.
- Читаемый импорт существующего `contentforge.android.yaml`.
- Умный поиск по настройкам: по словам «сеть», «думать», «токены», «редактор».

## 9. История, файлы, расходы

- Каждый запуск в своём каталоге с временем, ID, модельной схемой и снимком настроек. Не смешивать результаты разных запусков.
- `sources.md/json`, `research.json`, `outline.json`, `writer.md`, `seo.json`, `editor_pass_*.md`, `quality_pass_*.json`, `final.md`, `publisher.json`, `metrics.json`, диагностические логи.
- Отдельная кнопка «В Загрузки Android». Корректная обработка отсутствующего `termux-setup-storage` / storage bind в proot.
- Токены input, output, reasoning, cached по модели и агенту; время, повторы, число поисков.
- USD: точная стоимость только по возвращённым провайдером данным или надёжному generation endpoint, если поддержан. Иначе только явная оценка с маркировкой «примерно». Проверять, не создаёт ли сам просмотр стоимости новые биллинговые запросы.
- Жёсткие пределы числа поисков и количества дальнейших запросов можно обеспечивать локально. **Строго гарантировать потолок в USD до ответа нельзя**, если цена и реальная длина генерации не определены; нужен резерв/подтверждение и предупредительный стоп.
- Не показывать значения API-ключей в логах, экспортируемых настройках, traceback и скриншотах.

## 10. Безопасность и надёжность Android

- Ключ OpenRouter в приватном файле с chmod 600 или штатном безопасном хранилище Termux (если доступно). Не сохранять в GitHub и открытые файлы Downloads.
- Надёжный launcher `forge` из обычного Termux: учитывает, что внутри Ubuntu нужно исправлять PATH, выбирает /usr/bin/python3 и venv, показывает понятную ошибку если proot/git/python не установлены.
- Одновременные запуски не портят историю и конфигурации; атомарные записи и файлы блокировок.
- Пользовательские HTML/Markdown/URL — недоверенные данные. Локальный HTML не выполнять без нужды; сетевые ссылки ограничены http(s), запрет скрытых SSRF-переходов по локальным адресам в автономном режиме fetch.
- Тихий запуск без debug трасс, журнал ошибок доступен отдельно.
- Документация на русском, встроенные пояснения у каждой настройки.
- Уважать высоту/ширину терминала и экранную клавиатуру; fallback на простые цифровые меню, если сложный TUI недоступен.

## 11. Архитектура и этапы

Модули: `launcher`, `ui/screens`, `settings/schema`, `profiles`, `model_catalog`, `prompts`, `search`, `runner`, `runs/storage`, `accounting`, `diagnostics`. UI вызывает сервисы; сервисы взаимодействуют с существующими агентами. Не дублировать бизнес-логику и промпты в интерфейсе.

**Приёмка (по мере реализации):**
1. После установки пользователь вводит `forge`, меню открывается из Termux без ручного `proot-distro login ubuntu`.
2. Вставка 10-строчного ТЗ работает, Enter не запускает платный запрос.
3. Меняем модель на MiMo, запускаем один раз: все активные агенты действительно используют MiMo, включая редакторские повторения.
4. Назначаем другую модель одному агенту: остальные наследуют основную; смена режима на «Одна модель» отключает override.
5. При `max_search_calls=2` создаётся не более двух реальных поисковых запросов, в том числе при ретраях и tool calls; результаты и цена записаны в историю.
6. Редактируем копию оригинального prompt Writer, сохраняем, проверяем, что модель действительно получила изменённый текст; делаем Reset — оригинал восстановлен.
7. Для 3 проходов Editor сохранено до трёх версий и отчётов; при режиме «до N» возможна досрочная остановка.
8. Android «Загрузки» содержит финальный файл, пользователь легко находит и открывает его.
9. `contentforge --config ... generate` и существующие тесты не сломаны.
10. Нет утечек ключа в файлы результатов / git / логи. Ошибки сети и прерывания не удаляют существующие статьи.

**Этапы реализации:** (A) launcher + главное меню + ввод задания + модель/профили + результаты; (B) поиск с источниками и настоящим лимитом запросов; (C) per-agent параметры и reasoning с проверкой совместимости; (D) редактор промптов с версионированием; (E) история этапов, возобновление, расходы/бюджеты, диагностика. Каждый этап тестируется офлайн до API-запусков.
